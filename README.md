# 商家退款分析 Demo

得物商家后台退款分析交互演示，全部为生成的示例数据。演示日固定为 **2026-11-02**，有效数据截至 **14:30**，不依赖访问者的机器日期。

- 筛选器在同一行：统计口径、品牌、类目、出价渠道、日期、商品搜索、查询、重置，最右侧固定“下载明细”。窄屏可横向滚动筛选条。品牌、类目、渠道和搜索点击查询或按回车生效；重置保留统计口径、日期和当前趋势指标。
- 日期菜单支持自定义、今日实时、近1天（昨日）、近7天、近30天、自然周、自然月。草稿点击确定后生效，取消、外点和 Esc 均丢弃。自定义支持双月选区间或单日；自然周为周一至周日；自然月选择月份。
- 近7/30天截至昨天。当前自然周/月仅统计至昨天，至少有一天已结束才可选，并对比上一周期相同进度；完整历史自然月对比前一完整自然月，其他历史范围对比紧邻等长周期。趋势横轴展示本周期实际日期，上周期按序位对齐；上月短月没有对应日时留空。今日实时对比昨日全天绝对值，不计算变化率。
- 核心数据为“全部退款＝发货前退款＋发货后仅退款＋发货后退货退款”，保留等号和加号。每张卡展示退款金额和退款订单数；支付口径额外展示金额退款率、订单退款率。点击卡片标题保留当前指标切换类型，点击数值切换趋势；各指标名称带下划线和说明图标，悬浮或聚焦展示 PRD 中的指标释义和按日举例。
- 支付口径统计所选日期支付的订单，各自在支付后30天内成功退款的结果，并受统一演示截至时刻限制。退款口径按退款完成日期统计。退款订单数按子订单去重，退款金额按有效退款记录去重累加，部分退款只计实际金额。
- 两种退款率共用同批全部支付订单（含未退款订单）作为分母：订单退款率=退款子订单数/支付子订单数，金额退款率=退款金额/支付金额。按整段总量相除，不平均每日退款率。小时/日趋势按对应支付桶计算；无分母和缺失数据留空。
- 卡片与指标仅控制趋势；原因、商品和下载明细保持全局筛选范围。移除订单侧栏及其所有入口、商品分析导出按钮；保留商品/SKU展开。顶部下载成功退款记录明细 CSV，继承已生效的日期、口径和业务筛选，并包含筛选信息及汇总。

退款原因以明细表展示全部原因，不合并 Top 5；支付口径依次展示原因、金额退款率、订单退款率、退款金额、退款订单数，退款口径隐藏两种率。各指标可排序，表头说明图标提供释义与按日举例；原因退款率共用当前筛选范围的全部支付分母。

## 运行与验证

无构建依赖，运行文件为 `index.html`、`styles.css`、`refund-model.js`、`metric-definitions.js`、`date-picker.js`、`app.js`。

```bash
python3 -m http.server 8766
node tests/model.cjs
```

`refund-model.js` 可直接在浏览器使用，也可由 Node `require()`。`createData()` 返回独立支付子订单和关联成功退款记录。`summarize()` 的金额单位为分，趋势金额单位为元；`rate` 和 `amountRate` 为0到1的比例，`paidAmount` 为同批全部支付金额。

31项模型检查覆盖30天截止边界、部分退款、去重、两种率的独立分母、跨月/年、未结束自然周期、短月、数据截至时刻、缺失与零分母。指标释义及举例来源为已确认 PRD 的核心数据表（版本1109），集中维护于 `metric-definitions.js`。
