# 商家退款分析 Demo

得物商家后台退款分析交互演示，全部为生成的示例数据。演示日固定为 **2026-11-02**，有效数据截至 **14:30**，不依赖访问者的机器日期。

- 统计口径选项为“按支付时间口径 / 按退款时间口径”，默认选择支付时间口径。筛选器在同一行：统计口径、品牌、类目、出价渠道、日期，最右侧固定“下载明细”。窄屏可横向滚动筛选条。品牌、类目、渠道均以“标签：选项”展示，默认全部，选择后直接生效；选中具体选项后显示圆形清除按钮，点击仅将该项恢复为全部，其他筛选保持不变；顶部不再提供查询和重置按钮。
- 默认日期为近7天；日期菜单支持自定义、今日实时、近1天（昨日）、近7天、近30天、自然周、自然月。草稿点击确定后生效，取消、外点和 Esc 均丢弃。自定义支持双月选区间或单日；自然周为周一至周日；自然月选择月份。
- 近7/30天截至昨天。当前自然周/月仅统计至昨天，至少有一天已结束才可选，并对比上一周期相同进度；完整历史自然月对比前一完整自然月，其他历史范围对比紧邻等长周期。卡片保留上周期对比；今日实时卡片展示昨日全天绝对值，不计算变化率。图表标题为“数据趋势”，不展示类型或指标副标题；当前类型和指标分别由卡片及指标切换的选中态展示。趋势仅展示本周期数据，历史横轴为实际日期，实时横轴为小时；悬浮提示和纵轴范围均只使用本期数据，今日未来时段仍留空。
- 核心数据为“全部退款＝发货前退款＋发货后仅退款＋发货后退货退款”，保留等号和加号。每张卡展示退款金额和退款订单数，金额数字前加 ¥，金额名称不附加“（元）”，订单数不附加“单”；支付口径额外展示金额退款率、订单退款率。金额占比仅展示文案和数值，三类退款标题后提供分类说明问号。点击卡片标题保留当前指标切换类型，点击数值切换趋势；各指标名称旁使用圆形问号图标，悬浮或聚焦图标时，以深色带箭头浮层展示 PRD 中的指标释义和按日举例。
- 支付口径统计所选日期支付的订单，各自在支付后30天内成功退款的结果，并受统一演示截至时刻限制。退款口径按退款完成日期统计。退款订单数按子订单去重，退款金额按有效退款记录去重累加，部分退款只计实际金额。
- 两种退款率共用同批全部支付订单（含未退款订单）作为分母：订单退款率=退款子订单数/支付子订单数，金额退款率=退款金额/支付金额。按整段总量相除，不平均每日退款率。小时/日趋势按对应支付桶计算；无分母和缺失数据留空。
- 卡片与指标仅控制趋势；原因和下载明细继承顶部全局筛选范围，商品榜单在全局范围内独立搜索。移除订单侧栏及其所有入口、商品分析导出按钮；保留商品/SKU展开。顶部下载成功退款记录明细 CSV，继承已生效的日期、口径和业务筛选，并包含筛选信息及汇总。

退款原因以明细表展示全部原因，不合并 Top 5；支付口径依次展示原因、金额退款率、订单退款率、退款金额、退款订单数，退款口径隐藏两种率。右上退款类型筛选默认全部退款，可选发货前退款、发货后仅退款、发货后退货退款，仅影响原因表。各指标可排序，表头说明图标提供释义与按日举例；原因退款率共用当前筛选范围的全部支付分母。

Top退款商品区域提供“可搜索商品名称/ID”的独立搜索框，点击查询或按回车生效；搜索后重新生成商品Top20，分母包含匹配商品的全部支付订单，核心数据、趋势、原因表和下载明细不随局部搜索改变。榜单默认按退款金额降序取前20个商品，每页5个；支持指标排序、分页和SKU展开。支付口径展示8列，退款口径仅隐藏两种退款率，用户支付金额/支付订单数始终按所选周期内的支付统计。商品及SKU分别使用各自全部支付订单作为分母。退款原因按金额占比排序，以“原因（占比）”在同一行展示，超长省略；悬浮、聚焦或点击展示全部原因及占比。

## 运行与验证

无构建依赖，运行文件为 `index.html`、`styles.css`、四份 `design-*.css`、`refund-model.js`、`metric-definitions.js`、`date-picker.js`、`app.js`。

```bash
python3 -m http.server 8766
node tests/model.cjs
node tests/trend-view.cjs
```

`refund-model.js` 可直接在浏览器使用，也可由 Node `require()`。`createData()` 返回独立支付子订单和关联成功退款记录。`summarize()` 的金额单位为分，趋势金额单位为元；`rate` 和 `amountRate` 为0到1的比例，`paidAmount` 为同批全部支付金额。

34项模型检查覆盖30天截止边界、部分退款、去重、两种率的独立分母、跨月/年、未结束自然周期、短月、数据截至时刻、缺失与零分母。指标释义及举例来源为已确认 PRD 的核心数据表（版本1109），集中维护于 `metric-definitions.js`。

## 发布

GitHub Pages 从 `main` 分支根目录发布，推送后重新部署。

`tests/trend-view.cjs` 直接验证实际趋势渲染函数：上期不影响本期纵轴或悬浮内容，单点/全零/缺失数据、四类指标单位以及实时截止与未来留空，共5项专项检查。

核心区隐藏状态标签、口径说明、更新时间和对比日期；趋势区不展示类型/指标副标题、图例和图下注释，卡片内对比数据保留。


## 视觉规范

2026-11-02 对照得物 PC 2026 规范完成样式统一，来源为 Figma 文件 `y9NHBD0tILutqTkvvijHmp` 的 style、Layout、Menu、Button、Select、Table、Card、Tooltip、Date Picker 页。MCP 读取额度到达上限后的组件规则，通过已授权浏览器的正常 PDF 导出读取；内部规范原文不随 Demo 发布。

`design-tokens.css` 保存基础色、字体、间距、圆角和阴影；`design-layout.css` 负责页面骨架和表格；`design-system.css` 负责指标、趋势和浮层；`design-controls.css` 负责表单控件。四份样式在原有样式后统一覆盖，保留业务 DOM 钩子。

页面采用最新 Layout 的业务展开规则：导航 200px、顶栏 60px、页面外边距 24px、默认容器内边距 20px、模块间距 16px；优先于较早通用 Card 文档的 24px 容器规则。Button / Select 使用各自组件规则的 Medium 32px、14px 字号和 2px 圆角。表格数据保持 14px，通过容器横向滚动承载宽列；商品信息列固定。较窄内容区的四类指标通过局部滚动保留等号与加号关系。

指标问号采用深色、带箭头的纯文字提示，保留释义和按日举例；复杂商品原因列表使用独立浅色浮层。中文和数字使用规范字体名称及系统回退，不额外请求外部字体文件。页面主色为 `#01C2C3`，文字使用对应语义颜色，图表跟随容器宽度计算可读坐标。
