# 商家退款分析 Demo

得物商家后台退款分析交互演示。全部为生成的示例数据，未接入生产接口。演示日固定为 **2026-10-28**，有效数据截至 **14:30**，不依赖访问者的机器日期。

- 支持退款时间、支付时间口径；今日实时、近7天、近30天、自然日、自然周、自然月、自定义。近7/30天截至昨天；自然周为周一至周日，只可选已结束周期。示例可选日期从2026-01-01起，自然周从2026-01-05起。
- 历史范围显示较上周期变化率，自然月对比前一自然月，其余历史周期对比紧邻的等长周期。实时卡片展示昨日全天绝对值，不计算变化率。趋势提供本期实线和上周期虚线；短月无对应日期、今日未来时段和零支付分母留空。
- 核心数据为“全部退款＝发货前退款＋发货后退货退款＋发货后仅退款”。子订单去重计数，退款记录去重累计金额，三类子订单互斥完整。
- 支付时间口径增加退款率及其环比，三类共用全部支付子订单分母，含未退款订单。退款率按整段总分子／总分母计算；小时／日趋势按对应支付桶计算。商品和SKU使用相同支付集合，实时也展示退款率。
- 卡片只控制趋势类型；原因、商品、下钻及CSV导出使用本期全局范围。保留整块筛选吸顶、独立查看订单入口、订单和商品/SKU导出。

## 数据与测试接口

`refund-model.js` 可直接在浏览器使用，也可由 Node `require()`，不依赖DOM。`createData()` 返回独立的 `payments` 子订单集合和关联的 `refunds` 成功退款记录；数据覆盖2025-01-01至演示日，保证所有允许选择范围及其完整上周期都有数据。重复来源记录按退款记录ID去重，同一子订单多笔退款单量计1、金额累加。

主要API：`getPeriod(state, referenceDay)`、`query(data,state,range)`、`summarize(result,type)`、`buildTrend(data,state)`、`change(current,previous,complete)`。汇总金额单位分；趋势金额单位元、退款率为0到1的比例。`coverage` 区分缺失数据与真实0；支付和退款均按统一截至时刻过滤。
